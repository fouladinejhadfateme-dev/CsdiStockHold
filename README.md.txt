StockHold — سیستم مدیریت و رزرو موقت موجودی کالا
معرفی پروژه
StockHold یک Web API مبتنی بر .NET 8 است که امکان رزرو موقت موجودی کالا را فراهم می‌کند.
در این سیستم، مشتری می‌تواند با توجه به نوع مشتری و موجودی قابل رزرو، تعدادی از یک کالا را برای مدت مشخصی رزرو کند. پس از پایان زمان اعتبار رزرو، موجودی آزاد می‌شود.
قابلیت‌ها
•	ثبت رزرو موقت کالا
•	پشتیبانی از مشتریان عادی (Normal) و ویژه (Special)
•	محدودیت تعداد رزرو بر اساس نوع مشتری
•	تعیین مدت اعتبار رزرو بر اساس نوع مشتری
•	جلوگیری از رزرو بیش از موجودی کالا (Overselling)
•	پشتیبانی از درخواست‌های هم‌زمان (Concurrency)
•	جلوگیری از ثبت رزرو تکراری با استفاده از Idempotency Key
•	انقضای رزروهای منقضی‌شده
•	اجرای فرآیند انقضای رزروها به‌صورت Background Service
•	مدیریت خطاها از طریق Middleware
•	تست قابلیت‌های اصلی با استفاده از xUnit
قوانین کسب‌وکار
نوع مشتری	حداکثر تعداد در هر درخواست	مدت اعتبار رزرو
Normal	3 واحد	10 دقیقه
Special	10 واحد	30 دقیقه
موجودی قابل رزرو با در نظر گرفتن موجودی کالا و رزروهای فعال و معتبر محاسبه می‌شود.

API Endpoints
1. ثبت رزرو
POST /api/Reservations
نمونه درخواست:
{
  "productId": 1,
  "customerId": 1,
  "quantity": 2,
  "idempotencyKey": "reservation-key-001"
}
2. دریافت رزرو بر اساس شناسه
GET /api/Reservations/{id}
3. انقضای رزروهای منقضی‌شده
POST /api/Reservations/expire
مدیریت هم‌زمانی و موجودی
برای جلوگیری از رزرو بیش از موجودی کالا، عملیات بررسی موجودی و ثبت رزرو در یک تراکنش دیتابیس انجام می‌شود.
همچنین از قفل‌گذاری SQL Server با استفاده از UPDLOCK برای هماهنگی درخواست‌های هم‌زمان استفاده شده است.
Idempotency
برای جلوگیری از ثبت چندباره یک درخواست، از IdempotencyKey استفاده می‌شود.
در صورت ارسال مجدد درخواست با همان CustomerId و IdempotencyKey، رزرو قبلی بازگردانده می‌شود و رزرو جدیدی ایجاد نمی‌شود.
انقضای رزروها
رزروها دارای زمان انقضای مشخص هستند.
یک BackgroundService به‌صورت دوره‌ای رزروهای منقضی‌شده را بررسی و وضعیت آن‌ها را به Expired تغییر می‌دهد. با منقضی شدن رزرو، موجودی مربوطه برای رزروهای جدید قابل استفاده خواهد بود.

اجرای پروژه
برای Build کردن پروژه:
dotnet build
برای اجرای API:
dotnet run --project StockHold.API
پس از اجرا، Swagger برای مشاهده و تست API در دسترس خواهد بود.
تست‌ها شامل موارد زیر هستند:
•	جلوگیری از رزرو بیش از موجودی در درخواست‌های هم‌زمان
•	جلوگیری از ثبت رزرو تکراری با Idempotency Key
•	آزاد شدن موجودی پس از انقضای رزرو
•	ثبت کالای جدید
هدف پروژه
